    Quarkus Exam - Variation C : Potions & Difficulty Levels

    Description

    The aim of this application is to create a microservice that interacts with a public API about the Harry Potter world, specifically focusing on Potions, Alchemy, and Preparation Difficulties.

    Then we'll be importing the data from the public API into our PostgreSQL database and running Panache queries. Finally, we will publish events to Kafka whenever potions are added and process them in a second microservice.

    This is the project structure:

    • The api package is used to connect to the remote website.
    • The dto package is used to store in the database.
    • The model package is used to parse the API response.

    Setup

    Docker Compose

    Create a docker-compose.yml file to run PostgreSQL, Zookeeper, and Kafka:

    services:
  database:
    image: "postgres:14"
    container_name: "hp-database-c"
    ports:
      - "5432:5432"
    environment:
      POSTGRES_USER: postgres
      POSTGRES_PASSWORD: password
      POSTGRES_DB: quarkusdb_potions

  zookeeper:
    image: quay.io/strimzi/kafka:0.39.0-kafka-3.6.1
    command: [
      "sh", "-c",
      "bin/zookeeper-server-start.sh config/zookeeper.properties"
    ]
    ports:
      - "2181:2181"
    environment:
      LOG_DIR: /tmp/logs

  kafka:
    image: quay.io/strimzi/kafka:0.39.0-kafka-3.6.1
    command: [
      "sh", "-c",
      "bin/kafka-server-start.sh config/server.properties --override listeners=$${KAFKA_LISTENERS} --override advertised.listeners=$${KAFKA_ADVERTISED_LISTENERS} --override zookeeper.connect=$${KAFKA_ZOOKEEPER_CONNECT}"
    ]
    depends_on:
      - zookeeper
    ports:
      - "9092:9092"
    environment:
      LOG_DIR: "/tmp/logs"
      KAFKA_ADVERTISED_LISTENERS: PLAINTEXT://kafka:9092
      KAFKA_LISTENERS: PLAINTEXT://0.0.0.0:9092
      KAFKA_ZOOKEEPER_CONNECT: zookeeper:2181

    Project Starter

    Download from GitHub.

    Note on starter compatibility: - The starter project quarkus-exam is preconfigured with all necessary Quarkus extensions (quarkus-rest, quarkus-hibernate-orm-panache, quarkus-rest-client-jackson, quarkus-jdbc-postgresql, quarkus-smallrye-openapi). - The default HTTP port configured in src/main/resources/application.properties is 9180. Make sure to set quarkus.datasource.jdbc.url=jdbc:postgresql://localhost:5432/quarkusdb_potions to match your database service.

    REST Client

    1. In package com.course.api, create the PotionsApi interface and register it as a REST client using the Quarkus REST Client Guide: 
      package com.course.api;

import org.eclipse.microprofile.rest.client.inject.RegisterRestClient;
import jakarta.ws.rs.*;
import jakarta.ws.rs.core.MediaType;

@RegisterRestClient(baseUri = "https://api.potterdb.com")
@Path("/v1/potions")
@Produces(MediaType.APPLICATION_JSON)
public interface PotionsApi {
    @GET
    String getPotions();

    @GET
    @Path("/{id}")
    String getPotion(@PathParam("id") String id);
}
    2. Connect to the https://api.potterdb.com/ API to query potions (/v1/potions).
    3. Documentation reference: Potter DB REST API.
    4. Inject and test PotionsApi in ExampleResource to verify you receive the list and a single potion.

    Database

    You can use the Quarkus Hibernate ORM with Panache Guide as a reference.

    1) Create the Enum representing the different potion preparation difficulties:

    package com.course;

public enum Difficulty {
    Beginner,
    Ordinary,
    Moderate,
    Advanced
}

    2) Dataset file: Download potions.json and copy it into src/main/resources/potions.json.

    3) Create the entity classes in the existing project structure:

    • In com.course.dto.Potion: 

      package com.course.dto;

import com.course.Difficulty;
import com.fasterxml.jackson.annotation.JsonIgnoreProperties;
import io.quarkus.hibernate.orm.panache.PanacheEntity;
import jakarta.persistence.*;

@Entity
@JsonIgnoreProperties(ignoreUnknown = true)
public class Potion extends PanacheEntity {
    public String name;
    public String characteristics;
    public String effect;
    public String ingredients;

    @Enumerated(EnumType.STRING)
    public Difficulty difficulty;
}

    • In com.course.model.PotionModel: 

      package com.course.model;

import com.course.dto.Potion;
import com.fasterxml.jackson.annotation.JsonIgnoreProperties;
import com.fasterxml.jackson.annotation.JsonProperty;
import io.quarkus.hibernate.orm.panache.PanacheEntity;
import jakarta.persistence.*;
import java.util.List;

@Entity
@JsonIgnoreProperties(ignoreUnknown = true)
@NamedQueries({
    @NamedQuery(name = "Potion.getByEffect", query = "from PotionModel where attributes.effect like ?1")
})
public class PotionModel extends PanacheEntity {
    @JsonProperty("id")
    public String jsonId;
    public String type;

    @OneToOne(cascade = CascadeType.ALL)
    public Potion attributes = new Potion();

    public static List<PotionModel> findByDifficulty(String difficulty) {
        return find("attributes.difficulty", difficulty).list();
    }

    public static List<PotionModel> findByEffectLike(String effect) {
        return find("#Potion.getByEffect", effect).list();
    }
}

    4) Use ObjectMapper to load potions.json and persist them:

    // import com.fasterxml.jackson.databind.ObjectMapper;
ObjectMapper objectMapper = new ObjectMapper();
List<PotionModel> list = objectMapper
    .readerForListOf(PotionModel.class)
    .readValue(getClass().getClassLoader().getResourceAsStream("potions.json"));

    5) Create a REST /load endpoint in your resource to initialize the database with this potion dataset.

    6) Create Panache queries to implement the following REST methods in your resource:

}

}

// GET on /difficulties-count/{difficulty}
public long countByDifficulty(Difficulty difficulty) {
}

// GET on /effects/{effect}
public List<PotionModel> findByEffectLike(String effect) {
    // Use a @NamedQuery on PotionModel for this query

    Messaging

    We will now send a Kafka message containing the potion's name and difficulty to a second microservice each time a Potion is persisted in the database.

    Reference guide: Quarkus Kafka Getting Started.

    1) Add the Kafka messaging extension to your current project: 

    ./mvnw quarkus:add-extension -Dextensions="io.quarkus:quarkus-messaging-kafka"

    2) Create a shared class named PotionDTO: 

    package com.course;

public class PotionDTO {
    private String name;
    private Difficulty difficulty;

    public PotionDTO() {}
    public PotionDTO(String name, Difficulty difficulty) {
        this.name = name;
        this.difficulty = difficulty;
    }

    public String getName() { return name; }
    public void setName(String name) { this.name = name; }
    public Difficulty getDifficulty() { return difficulty; }
    public void setDifficulty(Difficulty difficulty) { this.difficulty = difficulty; }
}

    3) In the service/resource where potions are added to the database, send a message using an Emitter<PotionDTO> to channel potion-out.

    4) Configure the outgoing channel in src/main/resources/application.properties: 

    mp.messaging.outgoing.potion-out.connector=smallrye-kafka
mp.messaging.outgoing.potion-out.topic=potion-events
mp.messaging.outgoing.potion-out.value.serializer=io.quarkus.kafka.client.serialization.ObjectMapperSerializer

    5) Create a second Quarkus microservice named potion-listener: 

    ./mvnw io.quarkus:quarkus-maven-plugin:3.9.1:create \
    -DplatformVersion=3.9.1 \
    -DprojectGroupId=com.course.hp \
    -DprojectArtifactId=potion-listener \
    -DclassName="com.course.potion.PotionMessageResource" \
    -Dpath="api/potions-message" \
    -Dextensions="resteasy-jackson,quarkus-smallrye-openapi,messaging-kafka"

    6) Copy PotionDTO.java and Difficulty.java to this new project under com.course.

    7) Configure the incoming channel in application.properties of the potion-listener microservice: 

    quarkus.http.port=8081
mp.messaging.incoming.potion-in.connector=smallrye-kafka
mp.messaging.incoming.potion-in.topic=potion-events
mp.messaging.incoming.potion-in.value.deserializer=io.quarkus.kafka.client.serialization.ObjectMapperDeserializer
mp.messaging.incoming.potion-in.auto.offset.reset=earliest

    8) In PotionMessageResource, annotate a method named processMessage with @Incoming("potion-in") to receive instances of PotionDTO and store them in an in-memory thread-safe list (e.g. CopyOnWriteArrayList).

    9) Implement the following REST endpoints in PotionMessageResource: - GET /api/potions-message : returns the list of all received PotionDTO. - GET /api/potions-message/difficulty/{difficulty} : returns the total number of received PotionDTO belonging to the given Difficulty.

    Verification

    When both microservices and Docker containers are running: 1. Call /load on the first microservice (port 9180). 2. Verify in PostgreSQL that the potions are stored. 3. Call GET http://localhost:8081/api/potions-message and GET http://localhost:8081/api/potions-message/difficulty/Advanced to verify that Kafka events were successfully transmitted and aggregated.

    🚀 Advanced Challenge / Tâche Difficile (Bonus Points)

    Choose one (or both) of the following advanced challenges to earn bonus points:

    Challenge 1: Fault Tolerance & Local Database Fallback (Circuit Breaker)

    In production, external APIs like PotterDB can experience outages, high latency, or rate-limiting. Your microservice must survive without returning 500 Internal Server Error to the user.

    1. Add the SmallRye Fault Tolerance extension: 
      ./mvnw quarkus:add-extension -Dextensions="quarkus-smallrye-fault-tolerance"
    2. In your service or resource method calling the remote PotionsApi.getPotion(id):
    3. Add @Timeout(500): if PotterDB does not respond within 500 ms, interrupt the call.
    4. Add @Retry(maxRetries = 2, delay = 200): retry up to 2 times with a 200 ms backoff.
    5. Add @CircuitBreaker(requestVolumeThreshold = 4, failureRatio = 0.5, delay = 5000): trip the circuit breaker open for 5 seconds if 2 out of 4 consecutive requests fail.
    6. Add @Fallback(fallbackMethod = "fallbackGetPotion"): implement a fallback method that queries your local PostgreSQL database (PotionModel.find(...)) by name or ID.
    7. Demonstration: Show that when the network is disabled (or using an invalid remote base URL), calling your endpoint returns the local potion data from PostgreSQL seamlessly with HTTP 200 instead of failing.

    Challenge 2: Real-time Reactive Streaming via Server-Sent Events (SSE)

    In the potion-listener microservice (port 8081): 1. Instead of only querying static lists, expose a real-time reactive streaming endpoint: 

    @GET
@Path("/stream")
@Produces(MediaType.SERVER_SENT_EVENTS)
public Multi<PotionDTO> streamPotions() { ... }
    2. Connect your Kafka consumer stream directly to this Multi (using Mutiny BroadcastProcessor or @Channel("potion-in") Multi<PotionDTO>). 3. Demonstration: Open curl -N http://localhost:8081/api/potions-message/stream in a terminal or browser. Trigger /load or persist a new potion on microservice 1, and show that the event appears live in the stream as soon as it is emitted.

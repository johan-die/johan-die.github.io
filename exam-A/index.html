    Quarkus Exam - Variation A : Characters & Houses

    Description

    The aim of this application is to create a microservice that interacts with a public API about the Harry Potter world, specifically focusing on Characters and Hogwarts Houses.

    Then we'll be importing the data from the public API into our PostgreSQL database and running Panache queries. Finally, we will publish events to Kafka whenever characters are added and process them in a second microservice.

    This is the project structure:

    • The api package is used to connect to the remote website.
    • The dto package is used to store in the database.
    • The model package is used to parse the API response.

    Setup

    Docker Compose

    Create a docker-compose.yml file to run PostgreSQL, Zookeeper, and Kafka:

    services:
  database:
    image: "postgres:14"
    container_name: "hp-database-a"
    ports:
      - "5432:5432"
    environment:
      POSTGRES_USER: postgres
      POSTGRES_PASSWORD: password
      POSTGRES_DB: quarkusdb_characters

  zookeeper:
    image: quay.io/strimzi/kafka:0.39.0-kafka-3.6.1
    command: [
      "sh", "-c",
      "bin/zookeeper-server-start.sh config/zookeeper.properties"
    ]
    ports:
      - "2181:2181"
    environment:
      LOG_DIR: /tmp/logs

  kafka:
    image: quay.io/strimzi/kafka:0.39.0-kafka-3.6.1
    command: [
      "sh", "-c",
      "bin/kafka-server-start.sh config/server.properties --override listeners=$${KAFKA_LISTENERS} --override advertised.listeners=$${KAFKA_ADVERTISED_LISTENERS} --override zookeeper.connect=$${KAFKA_ZOOKEEPER_CONNECT}"
    ]
    depends_on:
      - zookeeper
    ports:
      - "9092:9092"
    environment:
      LOG_DIR: "/tmp/logs"
      KAFKA_ADVERTISED_LISTENERS: PLAINTEXT://kafka:9092
      KAFKA_LISTENERS: PLAINTEXT://0.0.0.0:9092
      KAFKA_ZOOKEEPER_CONNECT: zookeeper:2181

    Project Starter

    Download from GitHub.

    Note on starter compatibility: - The starter project quarkus-exam is preconfigured with all necessary Quarkus extensions (quarkus-rest, quarkus-hibernate-orm-panache, quarkus-rest-client-jackson, quarkus-jdbc-postgresql, quarkus-smallrye-openapi). - The default HTTP port configured in src/main/resources/application.properties is 9180. Make sure to set quarkus.datasource.jdbc.url=jdbc:postgresql://localhost:5432/quarkusdb_characters to match your database service. - The starter repository already contains com.course.Houses, com.course.api.CharactersApi, com.course.dto.Character, and com.course.model.CharacterModel.

    REST Client

    1. Register CharactersApi as a REST client using the Quarkus REST Client Guide. Add @RegisterRestClient(baseUri = "https://api.potterdb.com") or configure it via application.properties.
    2. Connect to the https://api.potterdb.com/ API to query characters (/v1/characters).
    3. Documentation reference: Potter DB REST API.
    4. Implement methods in CharactersApi to fetch:
    5. The list of characters (GET /v1/characters)
    6. A character by its ID/slug (GET /v1/characters/{id})
    7. Create corresponding test endpoints in ExampleResource to verify the client works properly.

    Database

    You can use the Quarkus Hibernate ORM with Panache Guide as a reference.

    1) The Enum represents the different Hogwarts houses (already present in the starter under com.course.Houses):

    package com.course;

public enum Houses {
    Slytherin,
    Gryffindor,
    Ravenclaw,
    Hufflepuff

    2) Dataset file: Download hp.json if needed (it is already included in src/main/resources/hp.json of the starter project).

    Use ObjectMapper to convert JSON from the resources folder to entity classes and persist them:

    // import com.fasterxml.jackson.databind.ObjectMapper;
ObjectMapper objectMapper = new ObjectMapper();
List<CharacterModel> list = objectMapper

    .readValue(getClass().getClassLoader().getResourceAsStream("hp.json"));

    Messaging

    We will now send a Kafka message containing the character's name and house to a second microservice each time a Character is persisted in the database.

    Reference guide: Quarkus Kafka Getting Started.

    1) Add the Kafka messaging extension to your current project: 

    ./mvnw quarkus:add-extension -Dextensions="io.quarkus:quarkus-messaging-kafka"

    2) Create a shared class named Perso: 

    package com.course;

public class Perso {
    private String name;
    private Houses house;

    public Perso() {}
    public Perso(String name, Houses house) {
        this.name = name;
        this.house = house;
    }

    public String getName() { return name; }
    public void setName(String name) { this.name = name; }
    public Houses getHouse() { return house; }
    public void setHouse(Houses house) { this.house = house; }
}

    3) In the service/resource where characters are added to the database, send a message using an Emitter<Perso> to channel character-out.

    4) Configure the outgoing channel in src/main/resources/application.properties: 

    mp.messaging.outgoing.character-out.connector=smallrye-kafka
mp.messaging.outgoing.character-out.topic=character-events
mp.messaging.outgoing.character-out.value.serializer=io.quarkus.kafka.client.serialization.ObjectMapperSerializer

    5) Create a second Quarkus microservice named message: 

    ./mvnw io.quarkus:quarkus-maven-plugin:3.9.1:create \
    -DplatformVersion=3.9.1 \
    -DprojectGroupId=com.course.hp \
    -DprojectArtifactId=message \
    -DclassName="com.course.message.MessageResource" \
    -Dpath="api/message" \
    -Dextensions="resteasy-jackson,quarkus-smallrye-openapi,messaging-kafka"

    6) Copy Perso.java and Houses.java to this new project under com.course.

    7) Configure the incoming channel in application.properties of the message microservice: 

    quarkus.http.port=8081
mp.messaging.incoming.character-in.connector=smallrye-kafka
mp.messaging.incoming.character-in.topic=character-events
mp.messaging.incoming.character-in.value.deserializer=io.quarkus.kafka.client.serialization.ObjectMapperDeserializer
mp.messaging.incoming.character-in.auto.offset.reset=earliest

    8) In MessageResource, annotate a method named processMessage with @Incoming("character-in") to receive instances of Perso and store them in an in-memory thread-safe list (e.g. CopyOnWriteArrayList).

    9) Implement the following REST endpoints in MessageResource: - GET /api/message : returns the list of all received Perso. - GET /api/message/house/{house} : returns the total number of received Perso belonging to the given Houses.

    Verification

    When both microservices and Docker containers are running: 1. Call /load on the first microservice (port 9180). 2. Verify in PostgreSQL that the characters are stored. 3. Call GET http://localhost:8081/api/message and GET http://localhost:8081/api/message/house/Gryffindor to verify that Kafka events were successfully transmitted and aggregated.

    🚀 Advanced Challenge / Tâche Difficile (Bonus Points)

    Choose one (or both) of the following advanced challenges to earn bonus points:

    Challenge 1: Fault Tolerance & Local Database Fallback (Circuit Breaker)

    In production, external APIs like PotterDB can experience outages, high latency, or rate-limiting. Your microservice must survive without returning 500 Internal Server Error to the user.

    1. Add the SmallRye Fault Tolerance extension: 
      ./mvnw quarkus:add-extension -Dextensions="quarkus-smallrye-fault-tolerance"
    2. In your service or resource method calling the remote CharactersApi.getCharacter(id):
    3. Add @Timeout(500): if PotterDB does not respond within 500 ms, interrupt the call.
    4. Add @Retry(maxRetries = 2, delay = 200): retry up to 2 times with a 200 ms backoff.
    5. Add @CircuitBreaker(requestVolumeThreshold = 4, failureRatio = 0.5, delay = 5000): trip the circuit breaker open for 5 seconds if 2 out of 4 consecutive requests fail.
    6. Add @Fallback(fallbackMethod = "fallbackGetCharacter"): implement a fallback method that queries your local PostgreSQL database (CharacterModel.find(...)) by slug/name or ID.
    7. Demonstration: Show that when the network is disabled (or using an invalid remote base URL), calling your endpoint returns the local character data from PostgreSQL seamlessly with HTTP 200 instead of failing.

    Challenge 2: Real-time Reactive Streaming via Server-Sent Events (SSE)

    In the message microservice (port 8081): 1. Instead of only querying static lists, expose a real-time reactive streaming endpoint: 

    @GET
@Path("/stream")
@Produces(MediaType.SERVER_SENT_EVENTS)
public Multi<Perso> streamCharacters() { ... }
    2. Connect your Kafka consumer stream directly to this Multi (using Mutiny BroadcastProcessor or @Channel("character-in") Multi<Perso>). 3. Demonstration: Open curl -N http://localhost:8081/api/message/stream in a terminal or browser. Trigger /load or persist a new character on microservice 1, and show that the event appears live in the stream as soon as it is emitted.
